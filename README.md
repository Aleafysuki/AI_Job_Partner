# AI Job Partner

**把你的经历与目标岗位放在一起，帮你看清「我有什么、岗位要什么、我缺什么，以及下一步应该做什么」。**

个人求职分析 / 简历优化 / 面试训练助手 —— 桌面端（v0.2）。

**v0.2 新增：能力问诊（把「熟悉 X」问成可判断的结论）、问诊结论转证据、能力库跨岗位保留、薄弱项训练。**
详见下方「从「知道缺什么」到「知道怎么补」」。

**v0.2 追加：面试复盘** —— 面试时录音并同步转写，结束后把「这个岗位实际是什么样」「我答得怎么样」
「适不适配」整理成一份可复核的报告。面对面只录麦克风，线上面试可以叠一路系统内录。
详见下方「面试复盘」。

---

## 它不做什么

- 不抓取招聘网站，不建职位库，不自动投递；
- 不建账号，不上传简历，不做社区；
- **不在面试进行中给任何提示** —— 复盘工具用在面试之后，不用在面试当中；
- 不评价面试官，不预测面试结果；
- 不给你一个「匹配度 82 分」。

## 它做什么

把简历和一个岗位放在一起，输出**可解释的判断**：

| 结论 | 含义 |
| --- | --- |
| 满足 | 有项目/工作类证据直接支撑这条要求 |
| 部分满足 | 有相关经历，但覆盖度不足或证据偏弱 |
| 缺少证据 | 你提到过，但只有自我声明，没有可核对的产出 |
| 明显缺口 | 所有经历里都找不到相关内容 |
| 无法判断 | 要求本身表述模糊，或关键信息被脱敏 |

每一条结论都能展开看到：命中了哪条要求、引用了哪条证据、证据强度怎么算出来的、依据哪条规则得出的结论。

## 核心概念：证据

系统严格区分两件事：

```
「我会 Python。」                        → 自我声明（self_claim） → 永远只能得到「缺少证据」
「用 Python + Playwright 开发采集工具，
  每天处理约 800 条数据，稳定运行 6 个月。」 → 项目证据（project） → 可能判为「满足」
```

所以档案里每一项能力都被分成三类：**已具备（有证据）/ 待证明 / 待学习**。
「待证明」通常是投入产出比最高的补强对象 —— 不需要新增能力，只需要把做过的事写清楚。

## v0.2：从「知道缺什么」到「知道怎么补」

v0.1 交付后暴露了三个问题，v0.2 针对性地解决它们：

**问题一：报告说「缺少证据」，但用户明明做过。**
→ **能力问诊**：五层递进问答（自评 → 具体场景 → 使用深度 → 产出结果 → 认知边界），
把「熟悉 X」问成六个等级之一，并把其中真正具体的部分写成一条证据。

**问题二：换个岗位重新整理简历，之前的积累全没了。**
→ **能力库跨岗位保留**：导入默认走合并，技能按标准名取并集、自评取更高的一侧、
证据按去重键去重、问诊结论按技能保留最新一次，并给出「新增了什么、保留了什么」的报告。

**问题三：知道缺什么之后，没有下一步动作。**
→ **薄弱项训练**：题目只来自这次匹配里真实没答上的要求 ——
能力缺口出概念题、缺少证据出「讲清楚」题、证据不足出对比取舍题；
附自查要点与常见追问，作答与自评记录在本地。

### 这一版最重要的一条设计约束

**问诊补充的证据，强度封顶为「中」。**

理由：证据强度衡量的是「这条经历能不能被外部核对」，而问诊是自述，没有外部载体。
如果允许它产出「强」证据，用户只要把问题答得漂亮，任何技能都会变成「满足」——
产品就等于自己废掉了 v0.1 立下的判断标准。

想升级到「强」只有一条路：补上链接、数字、时间这类可核对的东西，补完系统会自动重算。
所以规则不是堵死，而是**要么给可核对的载体，要么诚实承认这是自述**。

## 面试复盘

面试说完就过去了，事后只剩一个模糊印象。这一块把面试过程变成可复核的材料。

**三条使用路径，按「有没有录音」分：**

| 场景 | 怎么做 |
| --- | --- |
| 面对面 | 开会前点「开始录制」，只录麦克风，面试结束后生成报告 |
| 线上 | 同上，并打开「同时录制系统声音」——不打开会丢掉面试官那一半对话 |
| 没录音 | 把任何来源的转写文本（会议软件字幕导出、手机转写、手工记录）粘进来，一样出完整报告 |

**静默录制：面试期间不弹出任何东西。**

打开后：不弹 toast、不弹窗、不弹系统通知、不改窗口标题、不动托盘图标、不抢焦点，
主窗口直接从任务栏消失。结束方式有两条独立通道 —— 托盘菜单，或全局快捷键（默认 `Ctrl+Alt+R`）。

这么设计的原因很直接：面试时屏幕上多出来的任何东西都可能被对方看到，
而这件事跟「复盘」本身毫无关系。

**报告里有什么：**

- **机会侧 12 维**（D1–D12）：这个岗位实际在干什么、工作量换算成时间是否可行、
  9 类压力分别到什么程度、哪些话术需要验证、单位时间回报是多少；
- **表现侧 6 维**（P1–P6）：回答结构、事实密度、与岗位的对齐度、有没有讲清取舍、
  对不会的部分怎么处理、有没有主动问清关键信息；
- **岗位适配度**：10 个维度逐项打分，并标出哪些触碰了你写下的偏好边界；
- **三档决策表 + 三种情景推演 + 唯一一个下一步动作**。

每一条结论都挂着原始事实编号（`E7`、`E12`……），能一路回查到录音里说的那句话。

**刻意不做的三件事：**

1. **不做实时提示。** 面试进行中不产出任何结论。工具用在之后。
2. **不做说话人分离。** 单声道录音里谁在说话是按语用特征推断的，可能出错，界面会提醒你核对。
3. **不评价表达风格。** 音色、语速、口音、自信程度无法复核，不进入评分。
   反过来说，**承认「这块我不熟」是加分项，不是减分项**。

**平台差异（界面会如实告知）：**

| 平台 | 内录 |
| --- | --- |
| Windows | 直接可用 |
| macOS | 需要先装虚拟音频设备（如 BlackHole），否则内录拿不到声音 |
| Linux | 需要 PipeWire / PulseAudio 提供 monitor 源 |

拿不到内录时会**自动降级为只录麦克风**并把原因写在界面上，而不是整体失败。

**录音与隐私：**

录音按分片写在本机数据目录的 `recordings/<sessionId>/` 下，不上传、不联网。
转写是唯一会把**音频**发出去的功能，因此有独立开关（与「允许调用远程模型」解耦）——
你可以接受发脱敏文本、但不接受发录音，那就关掉它改用手工粘贴。

生成报告前会对转写做去标识化：称呼 → 「面试官」，公司名 → 「A 公司」，
电话 / 邮箱 / 身份证等按原有规则替换。**数字保留**（时长、薪酬、指标数量）——
它们是判断依据，模糊化等于废掉报告。

「放弃本次录制」也是把文件移到 `recordings/_discarded/`，不做物理删除。
录音不会重来，所以这套流程里没有任何一处会悄悄把它删掉。

> 开始录制前请确认：你所在地区与场景允许你对这场对话录音，且录音只用于你自己的复盘。

## 没有 API Key 也能用

默认走**内置本地规则引擎**：技能词典 + 结构化规则完成解析、拆解与匹配，完全离线、结果可复现。

需要更强的语义理解时，在设置页接入模型：

- **OpenAI 兼容接口** —— DeepSeek / OpenAI / Moonshot / 智谱 / DashScope / 硅基流动；
- **Ollama** —— 本机模型，数据不出机器。

模型只负责「把非结构化文本读懂」，**证据强度和硬门槛判断始终由本地规则完成**。
模型调用失败、返回非法 JSON、或者根本没配 Key，流程都不会中断，只是降级到规则引擎，并在界面上说明原因。

面试复盘也是同一套纪律：证据抽取、18 个维度、工作量测算、压力定级全部先跑一遍**确定性的本地规则**，
模型可用时才用它覆盖对应字段。**没配 Key 时复盘照样出报告**，只是结论更粗；
每条结论依然挂着原始事实编号，依然可以机械复核。

## 隐私

```
原始简历 → PII 识别（姓名/电话/邮箱/地址/身份证/社交账号）→ 脱敏 → 分析
```

- 档案里保存的是脱敏后的文本，真实值不落库、不进 Prompt；
- 每次调用模型前都可以要求人工确认，界面会展示**实际要发送的完整内容**；
- 每一次模型调用都留痕，可以逐条核对；
- 设置页有「允许调用远程模型」总开关，关闭后完全离线；
- 面试录音只写在本机 `recordings/` 下；转写是唯一会把音频发出去的功能，有独立开关；
- 复盘报告在生成前会去标识化，且报告本身不保留任何被替换掉的原文。

## 快速开始

```bash
npm install
npm run dev
```

第一次打开时点「**载入示例数据，先看效果**」，会用一份真实感简历 + 一份 AI Agent 岗位 JD
跑完整个链路，直接看到五种结论同时出现的效果。

其他命令：

```bash
npm run build        # 构建桌面端产物
npm run pack:win     # 打包（解包目录，不生成安装器，验证配置最快）
npm run build:win    # 生成 Windows 安装包 → release/AI-Job-Partner-0.1.0-setup.exe（约 112 MB）
npm run web:dev      # 浏览器开发模式（Web 版）
npm run web:single   # 单文件 HTML 演示版
npm run typecheck    # 三端类型检查
npm test             # 端到端链路测试（80 项断言）
npm run smoke:ui     # 渲染层：真实 Chromium 里点一遍全流程，逐页截图到 screenshots/
npm run smoke:app    # 桌面端整体：真实主进程 + IPC + SQLite，验证数据落盘与读回
```

Android 端：

```bash
npm run android:check    # 原生侧静态校验（括号/资源引用/通道一致性/XML 注释），不需要 SDK
npm run android:sync     # = 上一步 + web:android 构建 + 校验桥注入 + cap copy 进 Android assets
npm run android:open     # 用 Android Studio 打开工程，然后正常 Build
npm run smoke:mobile     # Android 外壳 + 原生桥契约 + 完整业务链路（393×851，截图到 screenshots/mobile/）
```

直接出 debug APK（已实测通过，产物见 `apps/android/release/`）：

```bash
export JAVA_HOME="/d/Program Files/Android/Android Studio/jbr"   # Windows 路径示例
export PATH="$JAVA_HOME/bin:$PATH"
cd apps/android/android && ./gradlew assembleDebug
```

> Android 端需要 **JDK 21 + Android SDK**。开发机上装的是 Android Studio，
> 用**它自带的 JBR 21** 与 `D:\Program Files\Android\Android Studio SDK` 即可 ——
> 具体路径、`local.properties` 的写法、以及首次构建踩到的四个坑，
> 都记在 [`docs/ANDROID.md`](docs/ANDROID.md) 第三节。
> 当前状态：**Java 原生一侧已编译通过并成功打出 debug APK，但还没在真机上运行过。**

`npm run smoke:app` 默认验证「源码 + 本地 Electron」；设置 `AIJOB_EXE` 可改为验证打包产物：

```bash
AIJOB_EXE="apps/desktop/release/win-unpacked/AI Job Partner.exe" node apps/desktop/scripts/app-smoke.mjs
```

它用独立的临时数据目录启动，不会碰你的真实数据。退出码 `0` = 全部通过，`2` = 环境受限只完成部分验证（**不是通过**），`1` = 真实失败。

`npm run smoke:ui` 会加载真实构建产物、自动走完「载入示例 → 解析 → 拆解 → 匹配 → 校验报告」，
再走一遍「导入转写 → 生成 18 维复盘报告」，把 17 张界面截图写到 `screenshots/`，
并输出各结论计数与渲染进程报错列表。
它复用项目自带的 Electron，不需要额外安装浏览器。

> **录音与内录没有被自动验证**，因为冒烟环境没有音频输入设备。
> 「假装录上了」比「没验证」更糟，所以冒烟脚本只覆盖不依赖硬件的那条路径
> （转写文本 → 复盘报告），录音需要在一台真有麦克风的机器上人工过一遍。

> 首次 `npm install` 若很慢，见 [`docs/BUILD.md`](docs/BUILD.md) 的镜像与故障排查一节
> （项目里提供了 `.npmrc.example`）。

`docs/debrief/` 是面试复盘框架的蓝本（维度为什么是这 18 个、风险信号为什么要给正面理解，
答案都在里面），它解释了**为什么这么设计**，而代码只能说明设计成了什么样。

## Android 端

同一个客户端，换一个宿主：**判断逻辑一行没动，界面一份代码两套外壳。**

- 桌面端（Electron）用双栏工作台外壳；Android 端用 Metro 风格外壳 ——
  Metro Blue 大色块头部、超大轻字重标题、横向 Pivot 分页导航、首页一组大色块磁贴。
  Metro 的视觉是**靠覆盖设计令牌**实现的（`styles-metro.css`），8 个页面一行 JSX 都没改。
- 桥不是 Capacitor 插件：原生侧一个通用 RPC，JS 侧装配成 `window.aijob`，
  于是 `DesktopBridge` 契约零改动，桌面端与 Android 端并排实现同一个契约。
- 存储换成原生 SQLite（WAL）、出网换成 OkHttp、文件走 SAF、录音分片落应用私有目录。

**⚠ 有四件事在 Android 上做不到，与桌面端不同：**

1. **静默模式无法不弹系统通知** —— Android 强制长时间录音必须有前台服务、必须有常驻通知，
   没有 API 可绕过。已把通知压到最低可见度，并让「结束录制」按钮走这条路
   （它成了静默模式下唯一能停掉录制的入口）。
2. **不做系统内录** —— `AudioPlaybackCapture` 需要被录的那一方同意，会议类 App 普遍关闭。
   线上面试因此录不到面试官那一半对话。
3. **没有全局快捷键**，由上面那条常驻通知替代。
4. **关掉了系统自动备份**（`allowBackup=false`）—— 否则档案与录音会被自动备份到 Google 云端，
   推翻「数据只在本机、不上传简历」的承诺。代价是换机不自动迁移。

关于「`restrict.mobile_client` 不是 v0.1 铁律里那条吗」这个问题，
以及完整的构建步骤、契约映射表、验证边界，见 [`docs/ANDROID.md`](docs/ANDROID.md)。
